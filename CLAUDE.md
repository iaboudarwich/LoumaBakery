# Louma Bakery: Project Memory

You are building/maintaining the Louma Bakery website. Read this every session.

## What this is
A neighborhood bakery on Wilshire (Santa Monica), open and trading (as of September 2026), with an inclusive-employment mission (many teammates have intellectual or developmental differences; the bakery exists partly to show that done right). Founder: Milla Ghandour; named for her sister Louma. Tone: warm, plain-spoken, proud, never saccharine.

## Stack & rules
- Astro, static output, TypeScript strict. No heavy UI framework.
- All content lives in content collections / config (src/data/*.json), never hardcoded in markup. CMS-editable via Decap (self-hosted bundle in public/admin; /admin-demo is the zero-cred test-repo demo, config generated on prebuild).
- Nav and footer are single shared components used by every page.
- Every visual effect is flag-gated in src/config/features.ts, wired into /review, and respects prefers-reduced-motion + mobile.
- HIDDEN FOR NOW (features.ts, all false): `cateringPage`, `careersPage`, `newsletter`. A hidden page is not built (the redirect in astro.config.mjs takes the route; the page also guards itself), 301s to / (netlify.toml + astro.config.mjs, via `hiddenRoutes`), is filtered from the sitemap and loses its footer link. `newsletter` off = no footer signup anywhere. Keep every page file, form, script, data field and CMS field. Turning one back on: docs/HANDOFF.md section 4 (flip the flag AND delete its netlify.toml block).
- Production URL from one SITE_URL config value. Netlify hosting. The menu is edited in the CMS. The old Google Sheet sync (scripts/sync-menu.mjs) is guarded: it refuses to run without --force (the sheet is out of date and in the old shape). scripts/check-menu.mjs compares menu.json with the owner's list (brief E.14).
- Forms are Netlify Forms: data-netlify + data-netlify-honeypot + hidden form-name, posted via fetch by src/scripts/forms.ts (newsletter in the footer, careers, catering; all three hidden for now). forms.ts finds forms by the hidden form-name input (Netlify rewrites <form> tags at deploy). Form detection is on; email notifications are not set up yet (docs/HANDOFF.md).
- No prices anywhere on the site except shop products. Menu items have no price field; catering tier prices stay in copy.json but are not rendered.
- Every page's meta description comes from its own copy via describe() in src/lib/seo.ts; the default title/description is the owner's tagline (copy.json home).

## THE DESIGN SYSTEM ("editorial slab", the only layout)
Source of truth for the brand: docs/BRAND.md and docs/brand/ (the designer's board). Tokens: src/styles/tokens.css.
- PALETTE: exactly eight colours. --red #ED2739 (Louma Red, PRIMARY), --burgundy #A10017, --peach #FF676C, --tangerine #FF8926, --fairy #DDEAC3, --butter #FBF5D4 (page background), --white #FFFFFF, --ink #1D1D1B (text). Derived values (--body, --muted, --hairline-strong, focus) are color-mix() of these eight only. No other hex or rgb() anywhere in src/.
- RED IS THE PRIMARY COLOUR, with one constraint: red text on butter is 3.86:1, so red TEXT must be 24px or larger (or bold at 18.66px or larger; the header nav links are Owners Narrow 500 at 24px for this reason). Small text sits in ink (or --body / --muted, both mixed from ink) or burgundy (7.56:1 on butter). Body links are burgundy and hover burgundy. Red is free for large display type, the drawings, and fills behind large text. White on red is 4.24:1: large bold text only. The footer is burgundy with butter text (7.56:1, any size).
- FLAT: no box-shadows, no gradients, no backdrop blur, anywhere. Depth = surface change + 1px hairlines (--hairline-strong). The header bar has no rule under it. No text on photos.
- BANDS: every section is one committed block: butter (the page), or a full-width colour block in burgundy, white or fairy (classes .block--burgundy/.block--white/.block--fairy). The colour change is the divider. The footer is a burgundy band too. Louma Red is never a band.
- TYPE: the Owners superfamily (Ohno Type Co), woff2 subsets in public/fonts, declared in src/styles/fonts.css. Four faces: Owners 500 (--font-display, regular width) for every title and heading (letter-spacing -0.015em, line-height 1.05; tokens --display-weight/--display-track/--display-lh), and for emphasis, labels, buttons, product names and the data voice; Owners 400 for body and menu item names; Owners Narrow 500 (--font-narrow) for the header nav (incl. the mobile sheet) and the footer's page links, "Visit" label and copyright; Owners Narrow 700 for the home hero tagline (round 5B; nothing renders it until then). Exactly four files in public/fonts: owners-400, owners-500, owners-narrow-500, owners-narrow-700. Preloads: owners-400, owners-500, owners-narrow-500. BODY TRACKING: --track-body 0.01em on every text element (a zero-specificity :where() rule in global.css, so it resolves at each element's own size); headings keep --display-track, and labels, buttons and form labels their own. No italic ships and font-synthesis is off, so never ask for italics or other weights. Licence: the files are desktop-licensed; a webfont licence from Ohno Type Co is required before launch.
- TYPE SCALE (tokens.css, used by every page in the layout system): --fs-display clamp(36px,4.6vw,64px) Owners 500 for page titles and the home tagline (.display, red); --fs-h2 clamp(24px,2.6vw,36px) Owners 500 for section headings (.h2, red); --fs-lead clamp(20px,1.8vw,26px) Owners 400 for intros (.lead, burgundy); --fs-body clamp(16px,1.15vw,18px) Owners 400, line-height 1.6, max 62ch; --fs-small 14px Owners 500 for labels (.label); --fs-nav 24px Owners Narrow 500 for the header links and the footer page links; --fs-item clamp(19px,1.4vw,20px) for menu item names (Owners 400) and product names (Owners 500). Base h1/h2/h3 sizes come from the same scale. text-wrap: pretty on paragraphs, balance on headings. The footer sets its own type (below).
- BODY TEXT (owner round 3): no ink body copy. Every page body paragraph is burgundy at --fs-lead (line-height 1.45, paragraphs --block-gap apart), like the home intro. One shared rule in global.css: `.lead`, `.page-intro .lede` and `.text-row-body p` (the Our Story and Initiative sections). Applies to /, /story, /initiative, /visit and the 404. Not to the header, footer, menu items and notes, shop products, labels or form fields (menu items, notes and shop cards are burgundy in their own sizes; no ink text on /menu or /shop either).
- SHAPES: square. No border-radius anywhere: buttons, chips, inputs, cards, images, nav.
- TYPE FLOOR: 13px minimum for all rendered text.
- FOOTER (designer round 5A): burgundy band, everything butter (text, links, icons, hairlines at 30%, the wordmark and the face). Body lines (address, hours, emails) in Owners 400 at --fs-body, line-height 1.4; the page links (--fs-nav, --fs-lead on phones), the "Visit" heading (--fs-small uppercase) and the copyright in Owners Narrow 500, the header's face. Padding --space-7 / --space-4; about 420px tall at 1440, 770px at 390. Columns: brand (face 160px wide, 112px on phones, static, aria-hidden, above the wordmark at the same width, cropped to its art); Visit in four groups: the address (the label --space-2 above it), the hours rows as one block, the two emails as one block, the Instagram and TikTok icons; lines inside a group sit one line-height apart, the groups --space-5 apart (3 x the label gap); the page links with no heading (Home, Our Story, The Louma Initiative, Menu, Shop, Contact). Icons: inline SVG, 24px, currentColor, in 44px links named by aria-label ("Instagram", "TikTok"), the svg aria-hidden; hover/focus shows the same 1px line under the icon. Links at least 24px tall (44px on touch). Butter focus ring. Underlines (owner round 3): every underline on the site is a plain solid line (no wavy or dotted; the old sketchy-link underline is gone). Never a colour change. No tagline line.
- LAYOUT: --container 1440px, --gutter clamp(16px,4vw,48px); every section aligns to the same edges. Vertical rhythm --section-y clamp(64px,9vw,144px), --block-gap clamp(24px,3vw,48px). The split page header (.page-intro-split > title + .page-intro-body, global.css; Menu and Shop): title over intro, side by side from 64rem (title columns 1-4, intro 6-12, tops level). - BUTTONS (global.css, defined once): .btn.btn-primary (the catering/careers submit and the 404 CTA) = solid burgundy, butter text, 48px min height, Owners 500 16px, hover red, focus ring 2px red offset 3px; a submit disabled while sending is a dashed ghost; the footer newsletter's .btn-coral keeps its own look. The Shop has no buttons: "Coming soon" is a plain label, a product with a link is a link.
- LABELS: .label = Owners 500 14px (--fs-small), burgundy on butter, butter on burgundy. The footer's "Visit" heading is Owners Narrow 500 --fs-small uppercase in butter. No dash/rule prefixes.
- NAV: one sticky flat row on butter on every page, 88px (64px below 48rem), no hairline under it: the red drawn wordmark (34-40px tall) left, the five links right (Home first; active on its own page) in Owners Narrow 500 24px (--fs-nav) red, hover burgundy, the active link with a 2px red rule. Below ~860px the toggle opens a full-screen butter sheet with the links in Owners Narrow 500 red at clamp(28px,3.6vw,48px). No transparent or hide-on-scroll state. The brand link's accessible name comes from its aria-label.
- DRAWINGS: src/assets/brand/ holds the designer's master art (see its README): wordmark.svg, baguette.svg, face.svg, each with a fixed viewBox role (the bread slice is the `bread-slice` doodle), plus doodles/ with 26 single drawings cut from the board (ingredients, herb, palm, hearts, sun, bear, live-laugh-louma and more). Use only these drawings, through Doodle.astro. The Menu and Shop pages have no drawings. - PHOTOS: straight, never tilted or rotated, rendered exactly as shot: object-fit cover inside a fixed aspect ratio per slot (.ph--portrait 4/5, .ph--landscape 3/2; Instagram tiles and shop tiles are square; the home hero fills the split hero's 7-column box, min(86svh,860px) tall, 4/5 below 48rem, every size a centred 4:5 crop; the home photo pair is 3/2 + 3/2, 4/5 stacked on phones). Every photo grid on / and /story is its own .section with a .grid-12 (gap --block-gap), so section spacing is --section-y everywhere. A photo's `focus` sets its object-position. No filter, blend, overlay, shadow or gradient on photos, and photos never animate. No text on photos.

## MOTION WHITELIST (complete; add nothing else)
- Doodle reveal (Doodle.astro, flag doodleDraw): one-shot 900ms cubic-bezier(0.22,1,0.36,1) when 30% of the drawing is in view. Every master is a filled outline, so it reveals left to right with a clip-path; stroked art would draw on via pathLength. Never left invisible (viewport watchdog). Drawings are accents, never background patterns; at most one per section (the letter's sun and moon are the specified exception).
- Sketch draw-on-scroll (flag scrollDraw; the 404 page's face only; the footer face is static): one-shot ~1.1s, 80ms subpath stagger; the outline traces in, then the fill settles back.
- Entrances: fade + settle 16px DOWNWARD (start 16px ABOVE) or fade in place; 500ms, same bezier, children staggered 80ms, once at ~30% in view. NEVER rise bottom-to-top.
- Photos never animate: no wipe, zoom, ken-burns, parallax or tilt. There is no marquee.
- Pen baguette (PenDraw.astro, flag penDraw; the home hero only, by the owner's request): the single-stroke baguette (baguette-stroke.svg, pathLength 1) loops forever on one CSS @keyframes, 4.9s: draw 1.8s ease-in-out, hold 1.2s, erase 1.4s from the start point forward (the dash offset keeps moving the same way), pause 0.5s. An IntersectionObserver pauses it off screen. Reduced motion or no html.motion: the whole baguette, static. The only looping animation on the site.
- Micro: button press scale, brand focus ring. Link underlines are plain solid lines (no wavy underline).
- Reduced motion: everything visible immediately in final state.

## COPY RULES (bans on sight)
- NO em dashes anywhere in rendered copy (verify dist HTML after building).
- No tricolons ("bread, pastry, and care"), no "not just X, it's Y", no empty superlatives (artisanal/finest/exceptional/premium), no jargon (elevate/journey/crafted/curated/nestled/indulge/savor/delight), no "we are passionate/committed/we believe", no throat-clearing openers.
- Text in story.json, copy.json and shop.json was written by the owner. Never rewrite, shorten or reword it, even when it uses words this guide otherwise avoids. Typos may be fixed only when asked.
- Caps: hero = one line (3-8 words) + one sentence. Menu items are the owner's names, with an optional short note (the owner's words, e.g. "Almond and pecan"). Story <= 300 words. Careers = plain sentences; the inclusive mission stated ONCE as plain fact. Visit = scannable mono block + one human line.

## STANDING RULES (never violate)
- The Initiative page (/initiative) NEVER discloses statistics about team members' disabilities. No replacement stats of that nature.
- Entrance animations never move content upward.
- The drawings in src/assets/brand/ (the three marks wordmark, baguette and face, and doodles/) are the designer's masters; never regenerate, redraw, trace or restyle them. Change them only from docs/brand/master. One derived file, by the owner's request: baguette-stroke.svg, the master baguette's centreline as a single stroke (method in src/assets/brand/README.md). It is the only stroke asset and is used only by PenDraw in the home hero; every other baguette is the filled master.
- Palette and fonts exactly as tokenized: the eight brand colours in src/styles/tokens.css, the Owners faces declared in src/styles/fonts.css (three in use).

## MOBILE / iOS RULES (locked)
- Viewport units: min-height 100vh fallback + 100svh pair. svh, never dvh. Hero-minus-header = calc(100svh - var(--nav-h)).
- Home hero 48rem to 64rem (tablets): the photo box is 3/4 and sets the row height (a full-height column cut the croissant grid too hard). Below 48rem: the photo first at 4:5, then the baguette and tagline; the tagline must stay within 1.3 screens at 390x844.
- Never width:100vw; html,body { overflow-x: clip } stays.
- Safe areas: viewport-fit=cover; pad CONTENT with env(safe-area-inset-*) via max(gutter, inset); band backgrounds reach true edges; nav + body offset grow by the top inset.
- Hover behaviors ONLY behind @media (hover:hover) and (pointer:fine); touch gets tap alternatives wherever hover carries meaning.
- Inputs >=16px computed (iOS zoom); inputmode/autocomplete set; never suppress user zoom; html.kb-open hides the sticky bar while a field is focused.
- Tap targets >=44px; -webkit-tap-highlight-color transparent + touch-action manipulation on controls.
- NO live SVG filters anywhere. FaceDraw (404) renders face-baked.svg (scripts/bake-sketches.mjs; equal to the master); the footer renders face.svg static; max 2 simultaneous draws, will-change on animating strokes.
- Nav: always-visible sticky bar (64px + safe-area below 48rem, 88px above; --nav-h, which anchor jumps and scroll-margin use); no hide-on-scroll.
- Reveals: one shared IO, fail-safe (hidden states only under JS-set classes; JS off = everything visible).
- Hero image <=150KB on mobile (AVIF, eager, fetchpriority=high). Fonts: the Owners woff2 subsets only (Latin, Latin-1, general punctuation, arrows), owners-400, owners-500 and owners-narrow-500 preloaded (owners-narrow-700 ships for the 5B hero tagline, not preloaded).
- theme-color AND body background both butter #FBF5D4 (Safari tints from either).
- Map: no iframe (CSP frame-src 'none'). /visit shows the hand-drawn map (map-hand-drawn.svg, butter on burgundy) and a plain "Get directions" link built from settings.json (siteConfig.directionsUrl).
- No sticky bottom bar on phones: the newsletter lives in the footer (switched off for now).
